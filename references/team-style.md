# Team Style Standard

This reference defines the default visual and presentation standard for the team-specific version of this Skill.

## 1. Default use case
Use this style by default for:
- master's thesis proposal defenses
- research proposal defenses
- methods-heavy academic presentations
- study-design and analysis-method slides

If an institution provides a mandatory template, keep its logo/footer rules but retain the information hierarchy below where possible.

## 2. Canvas and visual language
- Aspect ratio: 16:9 widescreen.
- Overall style: blue-white academic, restrained, clean, information-first.
- Default title band: deep blue to medium blue.
- Main background: white or very pale blue.
- Default text: dark navy.
- Use semantic accent colors sparingly:
  - blue = perception / primary structure
  - teal/green = objective behavior / implementation
  - orange = physical function / secondary module
  - red/pink = primary outcome / key risk construct
  - purple = psychosocial / exploratory module

Suggested palette:
- deep blue: #0D5A93
- medium blue: #2F94CC
- pale blue: #EAF4FB
- navy text: #173650
- teal: #168A7A
- orange: #C77914
- red: #C53E57
- purple: #7053B5

Avoid decorative gradients that reduce legibility. Use gradients only in title bars or large section headers.

## 3. Default slide architecture
Prefer one of these structures:
- title band + 2-column body + bottom interpretation strip
- title band + 3 equal information cards
- title band + full-width process / path / technical route diagram
- title band + figure-dominant layout + one short boundary note

Do not create a dense 'report page' inside a slide.

## 4. Figure-first rule
Prefer figures over prose for methods slides.
Priority order:
1. flowchart
2. variable framework
3. research question decomposition
4. technical route
5. model / path diagram
6. table only if relationships cannot be shown more clearly visually

Use actual editable slide elements when possible. If using an image as the full information panel, do not duplicate its content outside the image.

## 5. Text-density limit
Default limits per slide:
- outside-the-figure explanatory text: <= 5 lines total
- normal bullet count: <= 3 bullets
- normal bullet length: <= 1 line when possible
- footer / boundary note: 1 line
- title: 1 line

For figure-dominant pages, prefer:
- 1 focus sentence
- 0-2 clarification bullets
- 1 boundary/footer note

If the figure already contains labels and explanation, outside text may be zero.

## 6. Typography hierarchy
Suggested default sizes for 16:9 slides:
- page title: 28-34 pt
- card / section title: 20-26 pt
- body: 17-22 pt
- formulas / key variables: 20-28 pt
- footer / source / boundary note: 10-13 pt

Use bold for hierarchy, not for whole paragraphs.

## 7. Automatic academic boundary notes
Add or preserve these notes automatically when relevant.

### Cross-sectional study
Preferred wording:
> 横断面结果描述局部年龄差异与条件关联，不用于确认因果机制或预测个体未来风险。

Short version:
> 横断面关联不作因果解释。

### Path analysis / mediation-like diagram
Preferred wording:
> 路径为横断面统计分解，不识别时间先后或因果中介。

If a direct and indirect path model is shown, keep direct paths when the written analysis plan includes them.

### Simulated / predicted / schematic scatterplot
Preferred wording:
> 模拟示意，非实测结果；仅用于说明候选关系形式。

If direction is not prespecified:
> 方向不预设。

### Pending technical validation
Preferred wording:
> 参数为拟定方案，须经本地技术验收后冻结。

### Exploratory analysis
Preferred wording:
> 探索性分析按预设方案报告，不升级为主要发现。

## 8. Methods slide defaults for master's proposal defense
Prefer this order when supported by the proposal:
1. 研究设计、对象与样本量
2. 研究变量与测量框架
3. 特色任务 / 核心实验
4. 身体功能 / 客观行为测量
5. 测试流程与质量控制
6. 研究问题与分析策略
7. 主要模型与分层统计分析
8. 研究实施与技术路线

Do not force all eight pages when the study is simpler.

## 9. Redundancy rule
If a figure already states:
- variable names
- scoring ranges
- steps
- arrows / relationships
- model hierarchy
then do not restate them as bullets on the same slide.

Only add text outside the figure if it contributes one of:
- interpretation boundary
- role clarification
- implementation status
- one sentence telling the audience what to focus on

## 10. Oral defense optimization
Every slide should support a 20-40 second explanation.
The presenter should be able to answer:
- What does this slide show?
- Why is it here?
- What should the committee remember?

If a slide requires reading for more than ~20 seconds before its structure is clear, simplify it.
